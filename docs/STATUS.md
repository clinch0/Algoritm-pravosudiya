# Проверенный статус — 29.10.2026

## Реализовано

Проекты и загрузка TXT/DOCX/текстовых PDF; постоянный словарь с вариантами имён; шифрование оригиналов и ответов; обязательная серверная подготовка JSON и ручная проверка; ревизии и изоляция owner/project; читаемые заменители и локальное восстановление; сохранение ответов в диалоге.

Нормативный индекс FTS5 и семь MCP-инструментов; ресурс чтения нормы; неизменяемые версии импортируемых фрагментов. Начальный корпус — четыре статьи Конституции, а не полная действующая база законов. Документный retrieval выбирает ограниченные фрагменты обработанных документов. Локальный OpenAI-совместимый адаптер подключает Ollama/LM Studio, проверяет JSON/ID цитат/служебные токены.

## Реальная модель на машине разработки

Ollama 0.40.13 установлена. Стандартная загрузка из registry была отклонена защитой адресов: сетевой DNS возвращал адрес 198.18.*. Защита не отключалась. GGUF загружены из официального Qwen Hugging Face, проверены SHA-256, импортированы локально.

Qwen3-4B Q4_K_M скачана, но запуск при текущей нагрузке завершился ошибкой выделения CPU_REPACK памяти. Меньшая Qwen3-0.6B Q8_0 прошла реальный HTTP-сценарий с синтетическим документом: подготовленный запрос → найденные нормы/фрагмент документа → ответ → сохранение → endpoint восстановления. Первый прогон занял около 24 секунд. Это проверка интеграции, не юридического качества. Модель 0.6B слишком мала для заявления о надёжном анализе сложного дела.

Первый ответ изменил оформление заменителя. Добавлена нормализация только известного читаемого псевдонима с точным namespace; неизвестные и повреждённые маркеры отклоняются. Подстановка не угадывает личности. Исходное грамматическое склонение не восстанавливается.

## Границы готовности

Нет полной нормативной базы, автоматической проверки действующей редакции, независимой юридической оценки, embeddings и полноценной истории разговора в контексте модели, автономного многоагентного runtime, OCR, внешнего DeepSeek/GigaChat подключения, полного DAST, сертификации и подтверждения соответствия всем нормам РБПО/152-ФЗ. Каждый вопрос использует текущие документы и запрос; прежние ответы сохраняются в UI, но автоматически не становятся источником фактов.

Нулевая температура не устраняет ошибки. Принятый ID источника не доказывает соответствие вывода цитате. Ручной просмотр детектора не доказывает полноты обезличивания. Перед пилотом нужны задачи из SECURE_SDLC.md и юридическая проверка источников.

GitHub CI проверяется отдельно по коммиту; наличие файла workflow не означает, что удалённые jobs уже прошли.
