# Безопасная разработка и РБПО

Цель — включать безопасность в требования и проверку изменений. Это начальный процесс SSDLC, а не заявление о соответствии всем нормам РБПО или сертификации.

## Границы доверия

Браузер человека имеет авторизованный доступ к словарю. Backend хранит оригиналы/словарь/ответы зашифрованно, формирует подготовленную проекцию. Локальная модель видит только выбранные обработанные фрагменты и запрос; MCP источников не имеет интерфейса к словарю. Документы и найденные тексты — недоверенные данные, включая инструкции внутри них.

## Контроли и проверки

- Изоляция owner/project, повторная подготовка на сервере, отказ при устаревшей ревизии и неизвестном токене.
- Ручной просмотр результата детектора обязателен: regex не гарантирует обнаружение всех прямых и косвенных идентификаторов.
- Ограничения загрузки, страниц PDF, распаковки DOCX, числа документов/сущностей и размера контекста. OCR и отдельная песочница парсера отсутствуют.
- Модель: локальные адреса, отсутствие redirects/proxy, запрет cloud-имён, лимит ответа, проверка ID цитат и повторная проверка персональных данных в ответе. Это не семантическая проверка достоверности.
- UI экранирует недоверенный текст. API закрыто bearer-сессией; демо-учётка предназначена для localhost.
- Зависимости фиксируются, SBOM находится в docs/SBOM.cdx.json. Lock пока без хешей; образы Docker закреплены digest.
- CI: pytest, MCP, Playwright, Bandit и pip-audit. Внешний advisory timeout сохраняется как неполный результат. CI-статус сверять по конкретному коммиту.

## Процесс изменения

1. Описать актив/угрозу/воспроизводимый сценарий и ожидаемое поведение в OpenSpec.
2. Реализовать минимальное исправление с негативной регрессией на границе доверия.
3. Проверить функциональность, SAST/SCA, не публиковать секреты и рабочие данные.
4. Обновить фактический статус: какие команды прошли, что не запускалось, что требует независимой оценки.

## Незакрытые задачи перед реальными материалами

Права и основания обработки; юридическая проверка 152-ФЗ; классификация системы и применимые меры; модель угроз; отдельные роли и администратор; rate limiting; удаление/TTL проектов; миграции схемы; управляемый ключ и восстановление; закрытые резервные копии; сетевой запрет внешнего inference; sandbox парсеров; DAST; независимая оценка утечек/пропусков детектора и prompt injection; процесс регулярного обновления закреплённых образов/Actions.

Ссылка на стандарт или добавление слова «РБПО» не закрывает контроль. Для каждого требования нужен ответственный, проверяемая реализация и свидетельство проверки. Реальные результаты текущей сборки — docs/STATUS.md.
