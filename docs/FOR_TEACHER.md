# Что показать преподавателю

Разработан локальный прототип «Второе мнение»: проект → документы → постоянный словарь замен → просмотр подготовленного JSON → локальная модель + найденные источники → ответ с цитатами → локальное восстановление.

## Демонстрация на 7 минут

1. Открыть главную страницу, войти demo/demo123, создать «Учебное дело».
2. Загрузить вымышленный TXT: «Иванов Иван Иванович сообщил о публикации личной переписки. Он просит защитить частную жизнь».
3. Показать словарь: ФИО заменено на «Гражданин А» с namespace. Добавить второй документ с тем же ФИО — заменитель сохраняется. Вариант склонения привязать вручную к существующей сущности.
4. Спросить: «Какие гарантии неприкосновенности частной жизни закреплены в Конституции?» Показать JSON и подтвердить просмотр.
5. При настроенной Ollama/LM Studio получить ответ, раскрыть источники, показать восстановление. Отметить: проверяется существование ID, но правовой смысл проверяет человек. Фактический результат подключения — STATUS.md.
6. Во вкладке источников найти «частной»; показать статью 23, ссылку и ограничение редакции. Сейчас в нормативном индексе только статьи 2, 18, 21, 23 Конституции. Другие вопросы могут получить отказ.
7. Открыть /demo и показать формальный расчёт на синтетическом приговоре. Перезапустить backend и показать сохранённый проект/словарь.

## Архитектурные решения для обсуждения

- Один нормативный модуль используется backend и семью MCP-инструментами; агентам не отдаётся vault.
- UI, backend и БД выделены логически. Docker имеет два контейнера и постоянный том SQLite. Отдельный PostgreSQL нужен при многопользовательском распределённом запуске; пустой третий контейнер не добавлялся.
- RAG использует лексический поиск норм и обработанных фрагментов документов. Следующий этап — расширение проверенного корпуса, редакции на дату, независимый retrieval benchmark и сравнение embeddings.
- SDD оформлен в OpenSpec. Требования проверяются тестами; само наличие спецификации не доказывает юридической корректности.
- CI: функциональные тесты, Playwright, SAST и SCA. SSDLC начат, полного соответствия РБПО не заявляем.
- Обфускация не «обходит 152-ФЗ». Оригиналы, словарь и косвенные признаки требуют определения оснований обработки и мер защиты. До этого используются вымышленные данные.

Для согласования нужны узкая предметная область, перечень авторитетных редакций, критерии приемки и ответственный за юридическую проверку. Токен DeepSeek не нужен для обычных тестов; внешние модели не подключены к делам.
